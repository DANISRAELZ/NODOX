# Publication Evidence Index

## Purpose

This index maps software claims to evidence already present in the repository. It is intended to support a minimum publication-ready release by making claims, evidence, locations and interpretation boundaries explicit.

## Evidence Map

| Claim | Evidence type | Expected location | Publication relevance | Limitation or interpretation boundary |
| --- | --- | --- | --- | --- |
| Nodos Funcionales is a prioritization framework, not a clinical predictor. | Theory and conservative interpretation documentation | `docs/theory_of_functional_nodes.md`, `docs/interpretation_limits.md`, `docs/user_curated_conservative_interpretation.md` | Frames the software contribution without overstating therapeutic certainty. | Outputs are hypotheses and require downstream validation before biological or therapeutic claims. |
| The theoretical foundation defines functional nodes as interpretable therapeutic-priority candidates. | Conceptual model documentation and model tests | `docs/functional_node_model.md`, `docs/theory_to_software_mapping.md`, `tests/test_functional_node_model_publication.py` | Supports manuscript methods and terminology. | Conceptual consistency is not experimental validation. |
| The model separates therapeutic priority from evidence confidence. | Score documentation and publication GUI review contracts | `docs/scoring.md`, `docs/gui_publication_review_guide.md`, `tests/test_gui_publication_review_flow.py` | Prevents conflating ranking with evidence support. | A high `therapeutic_priority_score` does not imply a high `evidence_confidence_score`. |
| `user_curated` evidence is curator-provided and not automatically externally validated. | User-curated workflow documentation and validation tests | `docs/user_curated_validation_protocol.md`, `docs/user_curated_gui_onboarding.md`, `tests/test_user_curated_validation.py` | Clarifies provenance for manuscript and demo reporting. | Curator-provided evidence is not independent external validation unless separately documented. |
| Multi-organism orientation is supported by configuration and curated snapshots. | Architecture docs, example snapshots and tests | `docs/multiorganism_architecture.md`, `docs/organism_workflow.md`, `tests/test_multiorganism_orientation.py` | Shows the framework is not hard-coded to one bacterium. | Organism support depends on available input evidence and source quality. |
| The user_curated input workflow is documented and checked before scoring. | Templates, staging docs and quality gate tests | `data_templates/`, `docs/user_curated_pre_scoring_quality_gate.md`, `tests/test_user_curated_quality_gate.py` | Supports reproducible local data preparation. | Completeness checks do not certify biological truth. |
| Conservative interpretation is enforced across reporting surfaces. | Interpretation docs and GUI text-contract tests | `docs/user_curated_conservative_interpretation.md`, `docs/gui_run_review_publication_validation.md`, `tests/test_gui_run_review_publication_validation.py` | Keeps manuscript language aligned with software evidence. | Conservative wording does not validate candidates experimentally. |
| Pipeline execution is available through CLI and controlled GUI entrypoints. | Runtime docs and runner tests | `docs/gui_controlled_pipeline_execution.md`, `run_pipeline.py`, `src/nodos_funcionales/pipeline_runner.py`, `tests/test_pipeline_runner.py` | Demonstrates reproducible software execution paths. | Execution success is workflow validation, not biological validation. |
| GUI runs are isolated. | GUI execution and review documentation/tests | `docs/gui_controlled_pipeline_execution.md`, `docs/gui_run_review_publication_validation.md`, `tests/test_gui_run_review.py` | Supports auditability and prevents accidental overwrite of base results. | Isolation depends on preserving the documented write-boundary contract. |
| Publication packages are run-local for GUI runs. | Run-review validation document and package builder tests | `docs/gui_run_review_publication_validation.md`, `tests/test_publication_package_builder.py` | Enables manuscript/demo artifacts to be reviewed per run. | A package is a reporting artifact, not a validated biological result. |
| Comparison writes only to review. | GUI run-review documentation and tests | `docs/gui_run_review_publication_validation.md`, `tests/test_gui_run_review.py` | Keeps comparison artifacts separate from execution outputs and publication packages. | Comparison is a software artifact comparison, not proof of biological superiority. |
| Workflow validation is not biological or experimental validation. | Publication validation and release-readiness docs | `docs/gui_run_review_publication_validation.md`, `docs/publication_internal_validation.md` | Defines the correct scope of manuscript claims. | Wet-lab, clinical and pharmacological validation remain outside this release. |
| Scoring results require downstream validation before biological or therapeutic claims. | Scoring docs and interpretation warnings | `docs/scoring.md`, `docs/therapeutic_priority_decomposition_phase.md`, `src/nodos_funcionales/gui_run_review.py` | Protects against overclaiming from ranked outputs. | Ranked nodes are computational hypotheses only. |
| Testing strategy is offline-first for publication readiness. | Test strategy docs and offline test suite | `docs/testing_strategy.md`, `pytest.ini`, `tests/` | Supports reproducibility without mandatory network access. | Offline tests cannot guarantee freshness of external biological databases. |
| Demo readiness is based on the existing Pseudomonas aeruginosa publication demo. | Demo directory and expected outputs | `examples/pseudomonas_aeruginosa_publication_demo/` | Provides a concrete manuscript/demo example. | Demo outputs are controlled examples, not clinical or experimental confirmation. |
| Release readiness requires documentation, tests, citation metadata and a version tag. | Checklist and repository metadata | `docs/software_release_readiness_checklist.md`, `CITATION.cff`, release notes | Provides a transparent path to a minimum software release. | A release tag does not imply clinical readiness. |

## Limitations

This evidence index documents software readiness, reproducibility and interpretation boundaries. It does not convert computational scores into validated biological, experimental, pharmacological or clinical claims.
