# Pseudomonas aeruginosa publication demo

## Purpose

This directory packages a reproducible, publication-oriented demonstration case
for the functional nodes pipeline. It is based on the existing
user-curated Pseudomonas aeruginosa fixture and presents it as an executable
example that reviewers can inspect without depending on internet access.

Pseudomonas aeruginosa is used here because it is a well-known bacterial
pathogen with therapeutically relevant biology, including permeability,
virulence, resistance, and infection-context questions. In this repository it
is still only a demonstration organism. The software remains multiorganism and
does not define Pseudomonas aeruginosa as a default organism.

This demo supports conservative therapeutic prioritization. It does not
represent clinical validation, experimental validation, a predictor of clinical
efficacy, or a claim that any candidate is a therapeutic target. In short, it
does not represent clinical validation or experimental validation.

## Inputs

The `input/` directory contains controlled copies from the user-curated fixture:

- `gene_list.csv`
- `manual_curation.csv`
- `evidence_quality.csv`
- `manifest.yaml`
- `provenance.yaml`
- `notes.md`

The copied package preserves `provenance_type: user_curated`. It also preserves
the explicit negative provenance flags for online, demo, proxy, cache, and
controlled-reference evidence. The demo does not mix these inputs with external
providers or cached sources.

## Expected Outputs

The `expected_tables/` directory documents manuscript-ready output shapes. These
files are templates or expected structures, not fabricated results:

- `ranking_nodos.csv`
- `report_phase2.md`
- `candidate_explanations_simple.csv`
- `candidate_audit.csv`
- `evidence_strength_audit.csv`
- `layer_resolution_summary.csv`
- `publication_candidate_table.csv`
- `publication_interpretation_matrix.csv`

When the full pipeline is run with enough organism-specific layers, generated
outputs should be written under `output/` or another demo-specific workspace.
This demo does not write to global `results/`, `data_processed/`, or
`data_sessions/`.

## How To Run

PowerShell:

```powershell
.\examples\pseudomonas_aeruginosa_publication_demo\run_demo.ps1
```

Optional dry-run discovery check:

```powershell
.\examples\pseudomonas_aeruginosa_publication_demo\run_demo.ps1 -RunDiscoveryDryRun
```

Bash:

```bash
bash examples/pseudomonas_aeruginosa_publication_demo/run_demo.sh
```

Optional dry-run discovery check:

```bash
bash examples/pseudomonas_aeruginosa_publication_demo/run_demo.sh --run-discovery-dry-run
```

The default command prepares a local demo workspace under `output/workspace/`,
copies user-curated inputs into `data_user/`, preserves the source package under
`source_package/`, and writes a run note. The optional dry-run uses the existing
`run_pipeline.py` entry point in offline mode only. It is intentionally a
discovery/preparation check, not a full scoring run.

## Interpretation

Interpret the demo as a reproducibility and reporting example:

- `therapeutic_priority_score` is a prioritization score and must remain
  separate from `evidence_confidence_score`.
- `evidence_quality` and `evidence_strength` describe the state of evidence;
  they are not automatic validation.
- `evolutionary_escape_risk` is an unresolved-risk dimension unless explicitly
  supported by curated data.
- Insufficient evidence does not equal low risk.
- Conservative labels are used to keep unresolved evidence visible rather than
  converting uncertainty into positive claims.

## Manuscript Tables

The demo can support the following manuscript-facing tables once generated by a
complete run:

- Candidate ranking table.
- Candidate explanation table.
- Candidate audit table.
- Evidence strength audit.
- Layer resolution summary.
- Publication candidate table.
- Priority/confidence interpretation matrix.

Current templates document expected columns and limitations only. They should be
filled by the pipeline or by reviewed user-curated evidence, never by invented
results.
